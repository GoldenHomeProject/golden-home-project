## Failure 1: watchdog logs false `fail` entries on transient Pi network blips

**Evidence:**
- `{"t":"2026-10-08T14:54:31","label":"goldenhomeproject.com","http":"000000","status":"fail"}` and `meta_graph_api` and `ntfy_server` *all three* fail at the same timestamp — GitHub Pages, Meta's API, and ntfy.sh do not go down together.
- `{"t":"2026-10-28T02:28:28","label":"ntfy_server","http":"200000","status":"fail"}` — server actually returned 200, but the curl exit tripped a stale fallback, so the shell concatenated the real code with `"000"` and the regex rejected it.
- 100+ identical `"http":"000000","status":"fail"` rows across the three unrelated targets in the window, with no corresponding outage reports.

**Root cause:** `check_one()` combines curl's `-w '%{http_code}'` output with a `|| echo "000"` fallback, which (a) produces malformed codes like `000000`/`200000` and (b) treats a single transient Pi-side DNS failure as a real `fail` row, polluting the self-review input.

**Patch:** `pi/watchdog/ghp-watchdog.sh:55`

```diff
--- a/pi/watchdog/ghp-watchdog.sh
+++ b/pi/watchdog/ghp-watchdog.sh
@@ -55,7 +55,15 @@
 check_one() {
   local label="$1" url="$2" regex="$3"
   local code
-  code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || echo "000")
+  code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || true)
+  code="${code:-000}"
+  # A single '000' is almost always a Pi-side DNS/network blip, not a real
+  # outage — all three unrelated targets flap at the same second. Retry once
+  # so the jsonl (which feeds the self-review loop) stops recording ghost
+  # fails. FAIL_THRESHOLD=2 still gates real notifications unchanged.
+  if [ "$code" = "000" ]; then
+    sleep 2
+    code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || true)
+    code="${code:-000}"
+  fi
   if [[ "$code" =~ $regex ]]; then
     echo "ok|$code"
   else
```

**Why safe:** `FAIL_THRESHOLD=2` already requires two consecutive bad cycles before any user-visible notification, so a real outage (which lasts far longer than one 60s cycle plus a 2s retry) still fires the same way; only the transient-blip rows disappear.

**Verification:** `tail -f ~/ghp-watchdog/logs/checks.jsonl` for 2 hours after the systemd restart — zero `"http":"000"` rows for `goldenhomeproject.com` and `ntfy_server` under normal conditions, and the next weekly review should show the Watchdog section shrink by an order of magnitude.
