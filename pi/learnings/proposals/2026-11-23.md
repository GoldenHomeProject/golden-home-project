## Failure 1: Single-cycle DNS/network blips logged as service failures

**Evidence:** 32 scattered `"http":"000000","status":"fail"` entries across Nov 14 19:00 → Nov 23 08:24 — each is an isolated cycle on one target with no matching ~90s-later follow-up, so the next cycle recovered. Examples:
- `{"t":"2026-11-14T19:00:46-05:00","label":"meta_graph_api",...,"http":"000000","status":"fail"}` (no subsequent meta fail at 19:02:xx — recovered)
- `{"t":"2026-11-17T17:08:15-05:00","label":"ntfy_server",...,"http":"000000","status":"fail"}` (isolated)
- `{"t":"2026-11-23T08:24:35-05:00","label":"meta_graph_api",...,"http":"000000","status":"fail"}` (isolated, most recent)

These are all curl-level connect failures (never a real 5xx from the service), and volume is trending up (last week's review saw ~6; this week 32).

**Root cause:** `pi/watchdog/ghp-watchdog.sh:58` makes a single curl attempt — any transient DNS/TLS/local-uplink hiccup on a lossy residential WiFi flips the cycle to `status:"fail"` with no retry, polluting the durable log the self-review loop reads.

**Patch:** `pi/watchdog/ghp-watchdog.sh:55-64`

```diff
--- a/pi/watchdog/ghp-watchdog.sh
+++ b/pi/watchdog/ghp-watchdog.sh
@@ -55,6 +55,10 @@ notify() {
 check_one() {
   local label="$1" url="$2" regex="$3"
   local code
   code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || echo "000")
+  if ! [[ "$code" =~ $regex ]]; then
+    sleep 3
+    code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || echo "000")
+  fi
   if [[ "$code" =~ $regex ]]; then
     echo "ok|$code"
   else
     echo "fail|$code"
   fi
 }
```

**Why safe:** Retry only fires when the first attempt already failed, so the OK fast-path is untouched; sustained outages (Nov 14 burst) fail both attempts so `FAIL_THRESHOLD=2` alerting is preserved; worst-case added latency is 13s per cycle (3 targets × ~13s = 39s < 60s sleep), so the 90s cycle cadence is preserved; no state, alert, or jsonl schema changes — composes cleanly with PR #27's pending `"000"` cosmetic fix.

**Verification:** `sudo systemctl restart ghp-watchdog` then after 24h run `jq -r 'select(.status=="fail")|.t' ~/ghp-watchdog/logs/checks.jsonl | tail -50` — expect isolated-blip count to drop from ~4/day to near zero while any real sustained outage still shows consecutive ~90s-spaced fail entries on the same label.
