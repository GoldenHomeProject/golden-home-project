## Failure 1: watchdog single-shot curl records transient network blips as failures

**Evidence:**
- `{"t":"2026-09-15T04:49:46...","label":"goldenhomeproject.com",...,"http":"000000","status":"fail"}` + `meta_graph_api` + `ntfy_server` all failed at that same second (checks.jsonl) — three independent providers cannot fail simultaneously; the Pi's uplink did.
- `{"t":"2026-09-06T04:43:23","label":"meta_graph_api"...}`, `{"t":"2026-09-06T05:10:47"...}`, `{"t":"2026-09-06T05:58:21"...}` — three isolated single-target `000000` fails within 90 minutes with no clustering, i.e. individual timeout blips.
- Every failure this week has `http:"000000"` (the six-zero string is curl's "000" concatenated with the `|| echo "000"` fallback), meaning zero of them were real HTTP errors — 100% were connection-level.

**Root cause:** `pi/watchdog/ghp-watchdog.sh:58` performs a single 10s curl with no retry; a single DNS/TLS/handshake blip on the Pi's uplink is written to `checks.jsonl` as `status:"fail"`.

**Patch:** `pi/watchdog/ghp-watchdog.sh:55-64`

```diff
--- a/pi/watchdog/ghp-watchdog.sh
+++ b/pi/watchdog/ghp-watchdog.sh
@@ -55,10 +55,15 @@ notify() {
 check_one() {
   local label="$1" url="$2" regex="$3"
-  local code
-  code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || echo "000")
-  if [[ "$code" =~ $regex ]]; then
-    echo "ok|$code"
-  else
-    echo "fail|$code"
-  fi
+  local code attempt
+  for attempt in 1 2 3; do
+    code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null)
+    [ -z "$code" ] && code="000"
+    if [[ "$code" =~ $regex ]]; then
+      echo "ok|$code"
+      return
+    fi
+    [ "$attempt" -lt 3 ] && sleep 2
+  done
+  echo "fail|$code"
 }
```

**Why safe:** Same interface (`ok|CODE` or `fail|CODE`), same regex, same `FAIL_THRESHOLD=2` alert gating downstream — the only change is that a genuine outage now takes ~4 extra seconds to be declared, and a transient blip stops being declared at all. No new deps, no config, no paid services; also incidentally fixes the "000000" concatenation cosmetic since the `|| echo "000"` is gone.

**Verification:** `sudo iptables -I OUTPUT -p udp --dport 53 -j DROP; sleep 4; sudo iptables -D OUTPUT -p udp --dport 53 -j DROP` while watchdog is running — pre-patch this drops a `status:"fail"` into `checks.jsonl`; post-patch it does not. Then confirm one week later that the failure count in `~/ghp-watchdog/logs/checks.jsonl` is down materially from ~100/week.
