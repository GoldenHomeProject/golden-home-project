# GHP self-review — 2026-08-31

Generated by `pi/learnings/self-review.sh` on RaspberryPi5.

## Failure 1: Transient network blips logged as service failures; HTTP code recorded as "000000" instead of "000"

**Evidence:**
- 100+ lines of `{"http":"000000","status":"fail"}` for `goldenhomeproject.com`, `meta_graph_api`, `ntfy_server` in checks.jsonl — most are single-cycle blips (2026-08-17 09:23, 2026-08-18 13:07, 2026-08-19 05:40, 2026-08-20 12:25, 2026-08-21 05:55, 2026-08-22 20:51, 2026-08-25 21:43, 2026-08-26 15:10, …) with no adjacent failures.
- The recorded HTTP code is always `000000` (six zeros), never `000` — visible in every single fail line in the tail above.
- Same three labels flap independently on ~every day of the week, so this is not one bad upstream — it is the Pi's egress path.

**Root cause:** `check_one` in `pi/watchdog/ghp-watchdog.sh:55` (a) has no retry, so a single 10s curl timeout is logged as `fail`, polluting the self-review signal, and (b) when curl fails it writes `000` via `-w '%{http_code}'` AND then `|| echo "000"` appends another `000` — concatenating to `000000`.

**Patch:** `pi/watchdog/ghp-watchdog.sh:55-64`

```diff
 check_one() {
   local label="$1" url="$2" regex="$3"
   local code
-  code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null || echo "000")
-  if [[ "$code" =~ $regex ]]; then
-    echo "ok|$code"
-  else
-    echo "fail|$code"
-  fi
+  # Retry once with a short backoff so a single Pi-egress blip does not
+  # become a fail line. Two 10s timeouts inside ~12s is a real signal.
+  for attempt in 1 2; do
+    code=$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 "$url" 2>/dev/null)
+    [ -z "$code" ] && code="000"
+    if [[ "$code" =~ $regex ]]; then
+      echo "ok|$code"
+      return
+    fi
+    [ "$attempt" -eq 1 ] && sleep 2
+  done
+  echo "fail|$code"
 }
```

**Why safe:** Same output contract (`ok|CODE` or `fail|CODE`), same regex, same state machine, same `FAIL_THRESHOLD=2` alerting — only change is one extra probe on failure adding ≤12s to a 60s cycle. No new deps, no new env vars, no schema change to checks.jsonl (still one line per outer cycle).

**Verification:** `GHP_WATCHDOG_LOG_DIR=/tmp/wd GHP_WATCHDOG_STATE_DIR=/tmp/wds GHP_WATCHDOG_INTERVAL=5 bash pi/watchdog/ghp-watchdog.sh &` then `tail -f /tmp/wd/checks.jsonl` — point one target at `https://127.0.0.1:1/` to confirm fails now record `"http":"000"` (not `000000`) and unplug wifi for <15s to confirm no fail line is emitted for a single-cycle blip.
